# LinkForge

## 1. Problem Statement

LinkForge is a URL shortening service that converts long URLs into short, shareable links that redirect users to the original destination.

## 2. Functional Requirements

### MVP

- Create a short URL from a long URL.
- Redirect a short URL to its original URL.
- Support optional custom aliases.
- Support URL expiration.

### Out of Scope for MVP

- User accounts
- Advanced analytics
- Teams
- Billing
- QR code generation

## 3. Non-Functional Requirements

### Performance

- Redirect requests should normally complete within 100 ms at p95.
- URL creation requests should normally complete within 300 ms at p95.
- The system should support significantly more reads than writes because redirects are expected to dominate traffic.

### Availability

- Target availability: 99.9% for the public redirect service.
- A temporary failure in analytics or non-critical background processing must not prevent URL creation or redirects.

### Scalability

- The system should scale horizontally at the API layer.
- The design should allow caching of frequently accessed short URLs.
- The database should be capable of growing to tens of millions of URL records.

### Reliability

- A created short URL must not silently disappear.
- Custom aliases must be unique.
- Expired URLs must not redirect to the original destination.

### Security

- Validate and sanitize submitted URLs.
- Prevent abuse through rate limiting.
- Do not expose internal database or infrastructure details through the API.
- Protect administrative and internal endpoints separately when they are introduced.

### Observability

- Structured application logging.
- Request latency and error metrics.
- Monitoring for API failures and abnormal traffic patterns.

## 4. Assumptions

- LinkForge is a public URL-shortening service.
- MVP does not require user authentication.
- Redirect traffic is much higher than URL-creation traffic.
- Assume 100,000 new short URLs are created per day.
- Assume 10,000,000 redirect requests occur per day.
- Assume peak traffic can be approximately 10× the daily average.
- Short codes will be generated by the application.
- PostgreSQL is the primary source of truth for URL mappings.
- Caching is an optimization and is not the source of truth.
- The initial deployment can run in a single region.
- Advanced analytics, billing, teams, and QR codes are outside the MVP.
